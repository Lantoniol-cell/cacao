Results: the model versus the benchmark

Show the code 
import numpy as np
import pandas as pd
import plotly.graph_objects as go
from sklearn.metrics import balanced_accuracy_score
from _common_en import DATASET, METRIQUES, SERIE, MUET, READING, BENCHMARKS, YES_NO, lire, tableau

c = lire("modele_horizons.csv")
HORIZONS = {"sens": [1, 5, 20, 60, 120], "vol": [5, 20, 60, 120]}


def points_ic(t, series, titre, axe_y):
    """Gap to the benchmark and 99.4% interval, one point per horizon and per series."""
    fig = go.Figure()
    n = len(series)
    for k, (nom, (filtre, couleur)) in enumerate(series.items()):
        x = t[filtre]
        pos = [HORIZONS_POS[h] + (k - (n - 1) / 2) * 0.18 for h in x["horizon"]]
        fig.add_scatter(x=pos, y=x["ecart"], mode="markers", name=nom,
                        marker=dict(size=10, color=couleur, line=dict(width=2, color="white")),
                        error_y=dict(type="data", symmetric=False, array=x["ic_haut"] - x["ecart"],
                                     arrayminus=x["ecart"] - x["ic_bas"], color=couleur, thickness=2, width=4),
                        customdata=np.stack([x["horizon"], x["ic_bas"], x["ic_haut"]], axis=1),
                        hovertemplate=f"{nom}<br>Horizon %{{customdata[0]}} sessions<br>Gap %{{y:+.3f}}"
                                      "<br>99.4% CI: %{customdata[1]:+.3f} to %{customdata[2]:+.3f}<extra></extra>")
    fig.add_hline(y=0, line=dict(color=MUET, width=1.5, dash="dot"))
    fig.update_layout(title=titre, height=400, yaxis_title=axe_y,
                      xaxis=dict(tickvals=list(HORIZONS_POS.values()), ticktext=[f"{h} sessions" for h in HORIZONS_POS]))
    return fig

In brief

A machine learning model was trained to forecast cocoa from the 8 factor families. It was compared with simple models without any factor, which only look at the past price. If the factors carried information, the model should beat these simple models. It does not, at any horizon.

A few terms:

  • Price direction: will the price be higher or lower in 1, 5, 20, 60 or 120 sessions? A session is a trading day: 20 sessions are about a month, 120 about six months.
  • Balanced accuracy: the share of correct forecasts, corrected so that rises and falls weigh equally. 0.5 corresponds to chance, like a coin toss.
  • Volatility: the size of price moves, whether up or down. It is measured by the RMSE, the average forecast error: the lower, the better.
  • Benchmark: the best model without factors, for example “the recent trend continues” or “recent turbulence persists”.
  • Out of sample: each year is forecast with a model trained only on previous years, as in real conditions.

How to read the charts

Each point is the gap between the factor model and the best model without factors over 2010-2026. The bar is the 99.4% confidence interval, computed by block bootstrap. This level corrects for the 9 comparisons (5% divided by 9).

  • Above zero, the factor model does better.
  • It only beats the benchmark if the whole bar is above zero, in both readings.

Price direction

points_ic(t, {"Raw reading": (t["lecture"] == "brute", SERIE[0]),
              "Control reading": (t["lecture"] != "brute", SERIE[1])},
          "Price direction: balanced accuracy gap to the benchmark", "Gap (accuracy points)").show()

No interval lies entirely above zero. Up to 5 sessions, the model is at chance level, like the benchmark. At 60 and 120 sessions, it does worse than chance. It learns past regimes that do not repeat.

Year by year, at 20 sessions

Show the code 
p = pd.read_parquet(METRIQUES / "modele_predictions.parquet")
y = pd.read_parquet(DATASET, columns=["cible_hausse_20"])["cible_hausse_20"]
lignes = []
for nom, col in (("Factor model", "sens_20_brute_gradient_boosting"), ("Best without factors", "sens_20_brute_benchmark")):
    s = p[col].reindex(y.index)
    for a in range(2010, 2027):
        i = (y.index.year == a) & y.notna() & s.notna()
        if i.sum() > 20 and y[i].nunique() == 2:
            lignes.append({"annee": a, "serie": nom, "score": balanced_accuracy_score(y[i].astype(int), (s[i] > 0.5).astype(int))})
a = pd.DataFrame(lignes)
fig = go.Figure()
for k, nom in enumerate(["Factor model", "Best without factors"]):
    x = a[a["serie"] == nom]
    fig.add_scatter(x=x["annee"], y=x["score"], mode="lines+markers", name=nom, line=dict(width=2, color=SERIE[k]),
                    marker=dict(size=8), hovertemplate=f"{nom}<br>%{{x}}: %{{y:.3f}}<extra></extra>")
fig.add_hline(y=0.5, line=dict(color=MUET, width=1.5, dash="dot"))
fig.add_vrect(x0=2023.5, x1=2026.5, fillcolor=SERIE[1], opacity=0.07, line_width=0,
              annotation_text="2024-2026 crisis", annotation_position="top left")
fig.update_layout(title="Direction at 20 sessions: balanced accuracy by test year", height=380,
                  yaxis_title="Balanced accuracy")
fig.show()

Robustness tests

The same comparisons, changing one element at a time.

  • NASA rainfall replaces ERA5 and CHIRPS.
  • Oracle adds the weather actually observed over the next 7 days. This is deliberate cheating, which measures what a perfect weather forecast would bring.
  • GEFS forecasts give the same gaps as the baseline, within 0.01. They appear in the table.

What about forecasting the return directly?

A last attempt, decided after the results and therefore exploratory (protocol, point 13). Instead of the direction, the model forecasts the return over h sessions, that is, the percentage change in price. It is compared with the random walk, which assumes the price does not move, and with the past average of returns. 99% interval, corrected for 5 horizons.

Show the code 
g = lire("regression_rendements.csv").rename(columns={"ecart_rmse": "ecart"})
HORIZONS_POS = {h: i for i, h in enumerate(HORIZONS["sens"])}
points_ic(g, {"Raw reading": (g["lecture"] == "brute", SERIE[0]), "Control reading": (g["lecture"] != "brute", SERIE[1])},
          "Return: RMSE gap against the random walk (positive = model better)", "RMSE gap").show()

The model does significantly worse than the random walk at almost every horizon: the bars lie entirely below zero. It only guesses the sign of the return in 42 to 52% of cases. As the protocol required, no “forecast price curve” is therefore drawn: the best forecast of tomorrow’s price remains today’s price.
